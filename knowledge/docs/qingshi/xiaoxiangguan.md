## 1. 空地太多 —— **不是房子太小，是地被做成了草坪**

### 原文明写房子就该小

> 「上面**小小兩三間房舍**，一明兩暗，里面都是合著地步打就的床几椅案。」（第十七回）

正房实测面阔 9.6 m（`bayWidthsM: [3.0, 3.6, 3.0]`），**「一明兩暗」完全对得上**。
**房子没有问题。**

### 问题在地：原文说这块地上该有什么

> 「一帶粉垣，里面數楹修舍，有**千百竿翠竹**遮映。」（`07-07`，第十七回）
> 「一進門，只見**兩邊翠竹夾路**，**土地下蒼苔布滿**，中間羊腸一條石子漫的路。」（`07-41`，第四十回）

### 实测

| | 值 |
|---|---|
| 院墙（`xiaoxiangguan.courtyard-wall`）围合面积 | **2110 m²**（41 × 54 m） |
| 建筑占地（正房 65 + 后院退步 35） | **99 m²** |
| 建筑占院子 | **4.7%** |
| 竹 | **7 丛**（2 × `grove` + 5 × `clump`），合计约 200 竿 |

`plan.json` 的 `plants` 写着：翠竹「千百竿翠竹遮映，**成丛不成排**」、梨花、芭蕉、苍苔「土地下苍苔布满」。
`vegetation.ts` 的 `REGION_TREES` 给的是 `xiaoxiangguan: { mix: ['pear','locust'], density: 1 }`——**竹不在这张表里**，
竹是 `composer.ts` 的 `SCENE` 表里七条手写落位。

### 看到的

- **甬路两侧是草和大白野花，一竿竹都没有**——「**兩邊翠竹夾路**」没有落地；
- **苍苔在渲，但被亮绿草皮压过去了**。`mossInside: true` 确实挂在院墙上
  （`terrain-from-plan.ts` 按带 `mossInside` 的墙体线性算 `moss` 掩码），
  但最终 `moss` 还要乘 `(1 - path.w*0.85) * (1 - max(cobble,slab)) * 0.85`，
  而草的兜底权重把它盖住了；
- 满地大白菊花是**通用花散布器**撒的。**潇湘馆是"幽"，不该有草甸野花**——
  原文这个院子只有竹、梨、蕉、苔四样。

### 结论

> **不是加房子，是把草坪换成「竹夹路 + 苍苔」，并把通用野花从这个区撤掉。**
> 三件事的数据都已经在 `plants` 里写着了，只是散布器没照它办——
> 与正门「门前古松，门外净空，不作密植」同病。归**接缝 ②（选料规则）**。

## 2. 竹子穿墙 —— 就是其中一丛，能指名道姓

把 `composer.ts` 里七条竹丛落位（旧世界局部坐标 + `D_XIAOXIANG = [-114.4, 118.6]` 平移）
换算成世界坐标，逐条量到院墙折线的距离：

| 变体 | 世界坐标 | 到墙线 | 判定 |
|---|---|---|---|
| grove | (−100.2, 89.7) | 9.20 m | ok |
| clump | (−114.8, 103.0) | 9.93 m | ok |
| clump | (−105.0, 91.5) | 14.00 m | ok |
| **grove** | **(−93.9, 98.6)** | **2.90 m** | **穿墙** |
| clump | (−117.8, 103.4) | 8.68 m | ok |
| clump | (−120.4, 106.6) | 5.40 m | ok |
| clump | (−102.6, 109.0) | 11.00 m | ok |

`grove` 的做法（`builder/parts/zhiwu/bamboo.ts`）是**五丛错落塞在 6×6 m 里**，
种子点到 ±2.15 m、各丛 `spread` 约 0.42–0.55，**竹竿展开半径约 3.0 m，叶子更远**
（`groundRadius = 5.2`）。**2.90 m 的净距不够。**

图上（`x5_bamboo_wall_out.png`）一根竹竿从压顶穿下来、**插在白墙中段**
（没有偏移阴影，说明在墙体里不是在墙前），墙脚外还漏出一块土丘。

### 根因

`99-25`（footprint 两份真源）。这批坐标是旧 64×72 m 世界按 `D_XIAOXIANG` **整体平移**来的，
`composer.ts` 的注释自己写着：

> 「这里只按当前几何**短期重摆这三丛**，不做 occupancy prepass（**那是 99-25 的真修法，归 P4**）」

**单子 R 修的是落进房子 footprint 的三丛，落进墙里的这丛从来不在 R 的范围内。**
归**接缝 ③（占位真源）**。

## 3. 排水渠 —— 不只是"没做石压边"，**沙带宽度本身就是 bug**

`docs/ROADMAP.md` §PQ-3 早就写了：

> 现在是一条沙色生坑，**读感是地形坏了，不是没做完**——这是整张图里最像 bug 的一处。

**从来没有派过单。** 用户说"之前已经说过但没有修"，属实。

但真正的根因比"缺石压边"更具体：

```
引泉沟 polygon 实测宽 0.80 m（原文「開溝僅尺許」≈ 0.32 m，已经放宽了 2.5 倍）

builder/compose/terrain-from-plan.ts 的沙带：
  band = smoothstep(2.0, 0.2, sd) * smoothstep(-2.8, -0.6, sd)
                      ↑ 固定常数           ↑ 固定常数
→ 一条 0.8 m 的沟得到 0.8 + 2 × 2.0 = 4.8 m 宽的沙带
```

沙带的注释自己写着它是按**池岸**标定的：「水线一圈浅滩沙。园子里没有海滩，
**这只是池岸的湿脚**。」——照搬到一条尺许宽的沟上，就是一条 4.8 米宽的沙疤。

### 同一个教训，同一个文件里已经学过一次

往上 40 行：

```js
// warp 振幅随水面宽度收放：尺许宽的引泉沟经不起米级的扭动。
warpA: Math.min(1.1, inradius * 0.2),
warpB: Math.min(0.35, inradius * 0.06),
```

**`warp` 按 `inradius` 收放了，`sand`（以及同一趟算的 `wetBand`，±1.2 m）没有。**
修法就是同一个模式。记进 `docs/PITFALLS.md` `P-20`。

### ⚠️ 顺序不能反

**先收沙带，再做石压边。** 只做石压边的话，一条硬直线石边会浮在 4.8 m 的沙槽正中间——
`ROADMAP §PQ-3` 自己警告过：

> 真正的风险不在构件，在对齐……**两者必须由同一份数据生成**。

## 4. 顺带看到的三件（不在用户列的三条里）

1. **甬路是大块乱石板**，原文 `07-41` 是「**石子漫**」（小卵石拼花）。
   这是 backlog `D3-①` 的判断题，一直没定。
2. **路笔直**。原文是「**羊腸一條**」，该是曲的；现在路牙两侧平行笔直，读成市政人行道。
3. **院墙外东侧是裸土**，与院内没有任何过渡。

## 6. open_questions（乙待核）

1. 「開溝僅尺許」的"尺"按本项目口径是 32 cm（`chiCm: 32`），故原文沟宽约 **0.32 m**；
   `plan.json` 给的是 **0.80 m**，是为了第一人称下看得见而放宽的艺术选择——
   **但这个放宽没有留痕**（`water[]` 那条没有 `basis` 字段记它）。待补。
2. 「千百竿」是文学量词还是可折成密度？`07-07` 乙核已注明「规则未把它折成株距或面积，未越界」。
   本篇同样不折，只用它论证"现在 200 竿散点不够"。
3. 「兩邊翠竹夾路」的"夹"要多近？原文没给。是艺术选择。
4. 苍苔与草的权重关系（`moss` 最终乘 0.85 后仍被草盖住）是观感标定，**不是考据问题**，
   按「观感迭代期不要加门」应先调再焊。
