# 单子 BH：分区加载（区级流式）——先剖析与设计，停下定方案

> **依据**：用户 2026-10-01「之前提过的问题，分区加载，减少 cpu 负载」；`D-43`；规模架构设计 `docs/superpowers/specs/2026-09-14-scale-architecture-design.md` 接缝 ④（「五条里最贵、最容易做崩……必须有对照图」）；
> AX 单子末节的 AY 触发条件；`D-37`（散布旧窗口钉死 + 窗口外 32 m 块）。**标准动作见 `STANDARD-ACTIONS.md`。**
>
> **病**（验收人 2026-10-01 实测）：打开页面到能玩 **44 s**（5 区；建时约 35 s 全在主线程——理地、引水、植树、起屋叠石、调色），这段风扇狂转；
> 运行时整片建成区全在场景里，靠视锥剔除 + BC 远景档扛着。**每多建一个区，打开就更慢、常驻负载就更重**，19 区时不可接受。
>
> **本单只做 BH0（剖析 + 设计），停下给用户定方案，不写生产代码。**

## BH0 · 剖析

1. **建时按区拆账**：35 s 里哪些与「建成区数 / 窗口面积」成正比、哪些是全局一次性（天、云、水、着色器编译）。用 `profile-world` 或自己插桩，1 区 / 3 区 / 5 区 / 19 区（stub，只许对 worktree 跑）各量一次，给一张表。
2. **首帧可见需要什么**：出生在正门时，第一帧真正需要的是哪些区、哪些块（按视距 / 视锥），其余能不能推迟。
3. **常驻负载按区拆账**：每个区在场景里常驻多少 draw call / 三角 / 内存（GPU buffer）、每帧 CPU（isLOD 回调、植被簇 visible 重写等）。
4. **切分单位**：候选 ① 区（plan regions）② D-37 的 32 m 世界块 ③ 两者结合。地形、splat、植被、构件、碰撞、阴影各自能按哪种单位切，接缝在哪（高程连续、splat 接缝、D-37 旧窗口是一整块、占位场 occupancy 全园一张）。

## BH0 · 设计稿（写成 docs/superpowers/specs/ 下的 2026-10-01-region-streaming-design.md，新文件）

至少回答：
- **加载策略**：出生区 + 邻区先建（目标：打开到能玩 ≤ 15 s），其余按距离排队、分帧 / 空闲时 / worker 建；走近才建、走远卸载还是只隐藏；
- **远处怎么办**：没加载的区远看要不要代理（HLOD：体块 + 屋顶色 / 树冠团），否则远景会「空」；
- **确定性**：加载顺序不同，植被 / 构件的实例必须逐位相同（D-37 已给植被打好底；构件与规则散置要证明）；
- **工具**：capture / playtest / 对账门要能「全部加载完再量」，否则每个机位读数随加载进度漂；
- **分阶段**：建议拆成几张施工单、每张的判据与对照图、各自的回退办法；
- **风险清单**：哪些接缝最可能出可见裂纹，怎么测。
