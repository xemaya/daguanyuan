# 单子 BG：闲着少画 + 帧率上限 30——风扇别狂转

> **依据**：用户 2026-10-01「一打开这个网站，我电脑 cpu 风扇就狂转」，拍板「帧率上限降到 30」；`D-43`。
> 验收人实测（2026-10-01，1440×900 @2x，high 档）：游戏逻辑全部系统 **0.2 ms/帧**，`postfx.render` 主线程提交 **4 ms/帧**；
> 引擎只要页面可见就**以 60 帧满速一直渲染**——站着不动、暂停菜单、游园图开着、窗口失焦时都一样。风扇的主因是「不需要的时候也在满画」。
> **标准动作见 `STANDARD-ACTIONS.md`。**
>
> **文件域**：`engine/core/Engine.ts`（帧循环与节流）、`engine/ui/HUD.ts` / `engine/ui/MapOverlay.ts`（只许暴露「是否处于暂停 / 图开着」的状态，不改外观）、
> `projects/daguanyuan/main.ts`（接线）、相关测试。
> **不碰**：画质档位与后期参数（观感不许变）、vegetation / scatter / 构件、机位、基线、单子。

## BG1 · 帧率上限 30

`Engine.frameLimit` 默认 60 → **30**。URL `?fps=60` 可临时回 60（给对比用）。

## BG2 · 闲着少画

按状态给渲染节奏（**观感不变，只是不需要时不画**）：

| 状态 | 节奏 |
|---|---|
| 走动 / 转视角 / 跳 | 上限（30） |
| 站着不动、视角不动 ≥ 1 s | 15 帧（风吹草动照常，更新慢一半） |
| 暂停菜单 / 游园图开着 / 标题画面 | 画完当前帧**停**；状态变了（关菜单、窗口大小变、图里点了地方）立刻恢复 |
| 窗口失焦（`blur`，看得见但不在前台） | 2 帧 |
| 页面不可见 | 已经停（现状） |

- 「不动」的判据用玩家位置 / yaw / pitch 的变化量，不用输入事件（传送、落地也算动）。
- 动画时钟照常走（`clock.getDelta` 在降频时 dt 变大，`dt` 仍按现有 1/20 夹住）——**不许**让风、水、云在降频后「跳一下」看出断层，要是看得出就把降频档调高，回报写。
- 自适应分辨率的 governor 在降频状态下**不许**把降频误判成「fps 低」而降像素比——降频时暂停 governor。

## ⚠️ 硬约束：工具一个都不能受影响

`capture.mjs`、`playtest.mjs`、`visibility-probe.mjs`、`frustum-census.mjs`、`tree-census.mjs`、`record.mjs` 都在 headless 里跑、**没有指针锁、可能没有焦点**，
它们靠引擎一直在画。所以节流**必须**在以下任一条件下关掉：URL 带 `?fixed`，或页面上存在 `window.__CAPTURE__` / 工具设置的开关——
**你挑一种、把所有工具都接上**，并在 `STANDARD-ACTIONS` 之外的工具头注释写清。

**判据**：
- 四镜三次连拍：三角与 calls 与 `perf-baseline.json`（2026-09-30 版）**逐位相同**；`frameCostMs` 同量级；
- `playtest` PASS（脚下序列与改前相同段数）；`visibility-probe --entry X-05` 读数与 `experience-measured.json` 相同；`tree-census --dump` 逐字节相同；
- 真浏览器节奏实测（写一个 headless 探针，**不带**工具开关，模拟各状态）：每秒实际渲染帧数——走动 ≈30、静止 ≈15、暂停 / 图开 ≤1、失焦 ≈2；
- `check:all` 全过。
