## AJ1 · 白石台矶的质感（用户第 3 条）

> 「平台，现在是一个**大白铺出去的平台**，质感差了点。」

**现状**：`builder/parts/qiangyuan/forecourt-terrace.ts`（181 行），
`whiteStoneMaterial(1)` 一整片白，边缘一道西番草浮雕。

**根因一句话**：**它读成"一块"，不读成"砌出来的"。**

真的白石台基是**石作分层**，从下往上：

| 层 | 作用 | 视觉上给什么 |
|---|---|---|
| **土衬石** | 埋在地里、只露一线，比上层略出边 | 台基与地面之间有一道**出边的阴影**，不是硬切 |
| **陡板石** | 台基的立面 | **逐块**竖砌，块与块之间有竖缝 |
| **阶条石** | 压在台基顶边的长条石 | **逐块**铺，块与块之间有横缝；转角处有压缝关系 |
| **面层** | 墁地石板或方砖 | **有缝**，而且缝要成行成列，不是随机裂纹 |

**做法的核心是分块与缝，不是加纹样。**

**四条**：
1. **不许靠加雕饰解决。** `ART_DIRECTION.md` §10「具象雕刻要集中不要摊开」——
   西番草已经在边上了，台面再堆纹样只会腻。**要的是石作的"块"与"缝"。**
2. **缝要讲道理**：阶条石的长度、陡板石的分块、面层墁石的排缝，
   **三者的缝要能对上**（转角处尤其），随机撒缝会读成裂纹不是砌缝。
   尺寸没有原文出处，是艺术选择，留 `provenance.art`。
3. **近看工、中看色、远看形**（§10）。台矶大部分时候在中远景，
   **缝的对比度要压住**——一走近才看得见的浅缝，比远处就抢眼的深沟对。
4. **西番草"读成铁丝"（`C4`）本期不修。** 该文件的注释自己写着
   「这里原样复现同一个『缺点』」——**别顺手改它**，那是另一件事，
   改了会让这一轮的验收分不清是谁的锅。**但如果你发现分块之后它更扎眼了，写进回报。**

**判据**：新拍一张台矶贴脸 + 一张 `gate_approach` 正面，
**看得出是砌出来的白石台基，不是一块塑料板**。

## AJ2 · 抱鼓石：位置、朝向、形制（用户第 1 条）

> 「抱鼓石，现在**躲到了门里面**。正确的位置是**门前**，而且是**左右相对**的，
> 现在做成了都面向门外。抱鼓石比较好的话上面的原型是做成"鼓"的样子。
> 下方有**祥云、平台**，你考究一下抱鼓石的样式。」

### 考据（2026-09-15 查的，甲已核、乙待核）

来源：https://zh.wikipedia.org/wiki/门墩 与 https://zh.wikipedia.org/wiki/抱鼓石

**① 位置——用户是对的，而且原因在构造里**：

> 「门枕石**在中间有一个槽用于支撑门框**，**门内部分有一海窝**用于插入门纂（门轴的下端），
> 与固定在中槛上的连楹一起起到固定门轴……整体称门枕石，**门外部分称为门墩**。」

**所以：整块石头跨在门槛下，门内那头是海窝（承门轴），门外那头才是鼓。**
单子 AI3 把落位挪到「中柱缝」，等于把整块石头推进了门里——
**修对了"不在草地上"，修错成了"躲进门里"。**

**② 形制是三段，不是一个鼓坐在盒子上**：

> 「门墩通常由**须弥座，抱鼓或方箱，以及兽吻或狮子**几部分构成。
> **须弥座**是整个门礅的基础，一般会刻有**莲花**的形状，上面通常有**锦铺**。
> 抱鼓是一个**竖立着的鼓**，在**鼓面和鼓的侧面**通常雕刻有各种吉祥纹样。」

现状是「双层方基 + 一个鼓」，**须弥座那一层是假的**（代码注释：「双层，上层略收，
须弥座的意思，不做莲瓣」）。用户点名的「**祥云、平台**」正是这一段。

**③ 一块整石**：

> 「整个门枕石**由一块整石雕刻而成**。」

**所以三段之间不许有"零件摞起来"的接缝感**——比例要连贯，交接要有过渡（鼓下的托、
座与鼓之间的收分），不是三个 box 叠着。

**④ 鼓面的纹样**：抱鼓石「又称门鼓、石鼓、**螺鼓石**……**鼓面常刻有螺旋纹**，
故又称为螺鼓石。常刻龙凤、花鸟等纹路。」

### 做法

1. **位置**：让整块石头**跨门槛**——门内一头到门轴（海窝那一端，做不做海窝随你，
   但长度要够），**鼓落在门外**。位置仍由 `Frame.m` 推导（`columnX`/`columnD`/门槛位置），
   **不许拍一个数**；AI3 已经把 y 修对了（用 `b.platform.y` 而不是查地面高度），**别退回去**。
2. **朝向**：用户拍板 **左右相对**（两块互为镜像），不是都面向门外。
   即鼓的轴改成**左右向**，两块的鼓面朝两侧、互相对着。
3. **三段**：须弥座（**莲瓣 + 锦铺**，有出处）→ 鼓托（**祥云**，用户指定）→ 竖立的鼓。
   **一块整石的感觉**：三段共用一套收分，交接处倒角/过渡，不要三个独立 box。
4. **鼓面**：走「**螺鼓石**」那一读——**螺旋纹**。
   第一轮已经把鼓钉改成沿外缘一圈、更小，**那一步是对的，保留**。

### ⚠️ 一个判断题，不许自己拍板

**顶上的「兽吻或狮子」要不要？**

维基说门墩「在抱鼓或箱体上面雕刻有兽吻或狮子」。但用户 2026-09-14 已经拍板
**不加石狮**，依据是 `07-53`（石狮属**府门**）与 `07-01`（「並無朱粉塗飾」「不落富麗俗套」
是刻意把这座门写素的）。

**我的建议是不加**，保持素抱鼓——同一条理由既否了门前石狮，也该否鼓顶小兽。
**但这是形制取舍**：做出来给两档对照（素鼓 / 鼓顶小兽），**停下来回报让用户选**，
不要自己定死。

### 出处诚实

- **有出处**：三段构成、须弥座刻莲花+锦铺、竖立的鼓、鼓面螺旋纹、一块整石、门外部分才是门墩、门内有海窝；
- **用户指定**：左右相对、祥云；
- **无出处（艺术选择，留 `provenance.art`）**：所有具体尺寸、莲瓣与祥云的形状参数、收分比例。

**乙待核**：维基是通论，未核到清代官式门枕石的具体做法与尺寸规定
（《工程做法》有没有门枕石条目没查）。**按 `07-75`/`07-76` 的写法标「甲已核、乙待核」**，

## AJ3 · 瓦当要大，而且要真盖住缝（用户第 2 条）

> 「瓦当有了这个很好，但**太小了一点**，而且**挡不住瓦这层和木格中间的缝**，
> 现在**正面**看来还是比较差的。」

**现状**（`builder/parts/damu/building.ts`）：

```ts
const wadangR = Math.min(0.09, m.rafterPitch * 0.4);   // ← 被 0.09 m 硬顶封死
const wadangT = 0.05;
```

**两处要改**：

1. **尺寸该由垄距定，不是一个封顶常数。** 一垄一当——瓦当直径应当贴着**筒瓦垄距**，
   垄间才是滴水。现在 `min(0.09, …)` 那个硬顶让它在任何开间下都不超过 18 cm 直径，
   **五间大门的檐口上就显小**。去掉硬顶，让它跟着推导值走
   （`m.rafterPitch` 那一路），必要时另给一个"垄距"的推导。
2. **盖住缝是它的本职。** 用户说的「瓦这层和木格中间的缝」就是
   **屋面板下沿 + 连檐正面 + 椽头**那一条。瓦当滴水的**出挑与厚度**要真的把它遮住——
   现在 `wadangT = 0.05` 只有 5 cm，挡不住。**先量那条缝有多高多深，再定出挑。**

**判据（用户明确说了"正面"）**：
- `cu_gate_eave` 贴脸抬头；
- **外加一张正面平视机位**（`gate_approach` 那个距离），**正面看不出那条缝**。

### ⚠️ 这一件最可能吃爆预算

瓦当滴水是沿四条檐口的几百个小件，**放大 = 三角数直接乘**。

**硬要求**：收工时 `gate_approach` / `grass_close` / `mound_block` 三镜三角数
**不许比本单开工前高出 3%**，draw call 增量 **≤ 4**。
**量了才算**（标准动作第 8 条）。做不到先回报，**不要自己缩回去糊弄**。
