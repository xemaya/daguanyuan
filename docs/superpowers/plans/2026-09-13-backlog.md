## 第一梯队：真 bug 与会污染记录的（先做）

### B1 · 镜头晃得晕 3D 🔴

**用户 2026-09-13 走完的原话**：「晕 3d 跟行动的时候镜头有关，左右摇晃不平稳。」
（发烫那半已被 `frameLimit = 60` 解决，不用再动。）

四个嫌疑，**都在 `engine/player/PlayerController.ts` 与 `engine/core/Engine.ts`**，已量出确切值：

| 来源 | 现值 | 备注 |
|---|---|---|
| **视角侧滚** | 横移时 `roll = -ix * 0.026` rad = **±1.5° 地平线倾斜** | **最大嫌疑**。地平线倾斜是公认最强的晕动诱因 |
| 横向摆动 | `lat = sin(cycle) * 0.026` = **±2.6 cm**，每步一次 | 正是"左右摇晃"的字面来源 |
| 速度 FOV | 跑动时 `62° → 68°` **泵动** | 视场角变化是第二强的诱因 |
| 基础 FOV | **62°** | 桌面第一人称偏宽 |

**做法**：**加一个「减弱晃动」开关**（默认开或关由用户定），把侧滚、横摆、FOV 泵动
三项各给一个系数，**不要直接删掉**——它们在站定观景时是对的，问题只在行走中。

**⚠️ 要人判**：默认值该多轻、开关默认开还是关，**这是体感，你量不出来**。
给两三档（例如「原样 / 减半 / 关闭摇晃」）**让用户走一遍选**，不要自己定死。

### B2 · `capture.mjs` 的帧率对 WebGPU 是假数 🔴

**症状**：`capture.mjs` 报 `mound_block` **8 fps**、`pond_reveal` 25 fps；
按「预热后稳定段」重测**全部是 54–59 fps**（即 60 封顶）。

**根因**：WebGPU 的渲染管线是**懒编译**的，`capture.mjs` 只等 `settle = 1400ms`，不够。

**为什么必须修**：manifest 是我们的回归记录。**它现在每次都在记假数字**，
以后任何「帧率掉了」的判断都不可信。

**做法**：截图前加一轮预热（或把 settle 按 backend 分档），并**在 manifest 里记下
实际 backend 与统计口径版本**——WG 已经把 `render.calls` / `render.drawCalls` 的
口径问题暴露出来了，两件一起收。

### B3 · 补一条漏记的 `missing`

单子 P 当时守规矩没碰 `missing.rules.json`（那时划给了别人），留下一条没记：

> **「一座五间 Tier A 门屋该不该走江南参数集」**——「泥鳅脊」本身就是江南脊名，
> 原著用江南词描述这座门，而 `menSpec` 走的是 `fashi`。这处口径错位现在是绕开的，没解决。

按 `07-76` 的措辞补进 `missing.rules.json`，`paramSet: "none"`。

### C2 · 树冠「假发片」

**用户 2026-09-13**：「植物……质感还是假发片。」

树种确实换过了（`elm`/`locust`/`pine-old`/`cypress`/`willow`/`pear`/`peach`/`haitang`），
**没换的是树冠的做法**——仍是 `count: 150 + cR*cR*...` 张**交叉卡片**，走近了就是一片片平面。

WG 之前不能动（`foliage-materials.ts` 是 WG2 的移植目标），**现在可以了**。

**⚠️ 这条很大，先给方案再动手**：是换成实体小枝、加法线让卡片不那么平、还是近景换一套 LOD？
**给出选项与三角数代价，停下来回报。**

### C3 · 西番草返工

单子 P 的第 ④ 件做成了**一条带小结点的锯齿细线**，不是卷草：

- **「卷草」的定义就是卷**——螺旋、C 形、S 形的回转，锯齿一个卷都没有；
- **「鑿成」是刻进去**，现在像贴在白石表面的一根铁丝，没有浮雕的明暗；
- 太细，实际视距下读成一道划痕。

依据见 `07-76` 第 ③ 档（西番草 = 缠枝卷叶）。**注意 `ART_DIRECTION §10`：
具象雕刻要集中不要摊开，别顺手把五间都雕满。**

### C4 · 远处的虎皮石读成规则锯齿带

近景对（不规则乱砌看得出是石头），**远处那道墙的墙基读成规则重复的锯齿**。
是尺度 / mipmap 的事，参照 `P-07`（瓦垄那次）的思路：先算它在屏幕上占几个像素。
