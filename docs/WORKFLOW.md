# 工作方法：一景一轮怎么转

> 2026-09-17 定稿。把 2026-09-14 到 09-17 这四天（正门四轮 AI→AJ→AN2/AP/AS→AT→AU 冻结，翠嶂两轮 AM→AV，评审 codex 一份）
> 里反复用、反复踩、最后站住的那套做法写成一页。**规矩本身在 `docs/superpowers/plans/STANDARD-ACTIONS.md`（施工 agent 读）和
> `CONTRIBUTING.md`（所有人读），这一页讲的是它们怎么串成一轮、谁在哪一步做什么、为什么这么分。**
> 新 session 先读这一页，再读 `docs/ROADMAP.md` 的「交接」。

## 1 三个角色，谁做什么

| 角色 | 做什么 | 不做什么 |
|---|---|---|
| **用户** | 实地走园子提观感；拍板判断题（位置 / 数量 / 有无 / 繁简 / 冻不冻结）；派 agent；合回 | 不看图判档位（颗粒、AO 半径这类看不出的，验收人定） |
| **验收人**（Claude 主 session） | 诊断、写景需求文档、写单子、给派单命令；**验收：自己跑门、量数、拍图、看图**；记账（台账 / 决策 / 坑 / 交接） | 不施工（除了文档、工具转正、基线）；不采信 agent 自报 |
| **施工 agent**（用户另开的 session） | 按单子做，守文件域，一件一提交，回报数字；判断题停下来 | 不改机位、不改基线、不改单子、不顺手修别的 |

**为什么这样分**：施工者不能给自己验收——AT 只改了计划文件就报「提交完成」，AM 在基线里签了验收人的名，AV 把 +16% 三角归因成「看得更深」而实际门口视锥里的树少了 25 棵。**每一次都是验收人自己量出来的。** 把"做"和"验"放在两个人手里，是这套方法唯一的前提。

## 2 一轮六步

```
用户实地走 → ① 诊断（量）→ ② 需求（景需求文档）→ ③ 单子 → ④ 派单 / 施工 → ⑤ 验收 → ⑥ 记账 → 用户再走
```

1. **诊断先量再说**。观感一句话背后是几个具体的病，每个病要有一个数：翠嶂「秃」= 门轴 x=55 上没有石头 + 36 棵撒的树 + 灌木 0 藤萝 0 + 坡 12°。工具：机位图（`tools/capture.mjs`，不够就临时机位）、`tools/tree-census.mjs`、`manifest-diff --coverage`、脚下序列。**没数的诊断不进单子。**
2. **需求写进 `knowledge/docs/scenes/<景>.md`**（`D-29`）：该是什么（原文）/ 现在是什么（量过的）/ 怎么验（判据表）。它是开单依据，也是验收对照表。翠嶂的轴线错就是没有这一页才漏的。
3. **单子** `docs/superpowers/plans/<日期>-<编号>-<名>.md`：头部 = 依据 + 文件域 + 不碰；正文每件 = 病 → 做法 → 判据；判断题标「⚠️」；末尾 = 开工基线 / 验收表（抄需求文档 §7）/ 回报清单 / 规模与风险。**判据必须是一个能量出来的数或一张指定机位的图。** 单子定稿后施工 agent 不许改它。
4. **派单命令**固定格式（§4）。并行按**区域**切文件域，三轨是验收带宽上限。
5. **验收清单**（§3）。全部自己跑。
6. **记账**六处：`docs/reviews/…-response.md` 加一节（数字、判断、发现）；`DECISIONS.md`（拍板了的）；`PITFALLS.md`（踩了的）；`ROADMAP.md` 交接表（状态）；景需求文档（agent 改现状列，验收人补记）；基线（`perf-baseline.json` history / `coverage-baseline.json` note，只有验收人抬）。

## 3 验收清单（验收人照着跑，缺一项就不算验过）

1. `git log --oneline <上次>..editor` + `git worktree list`：**合回没有、合回了几个提交**，不信"提交完成"四个字。
2. `npm run check:all`（九门 + 测试）exit 0；`node tools/playtest.mjs --url …` PASS，动了地面的看脚下序列头几段。
3. 四镜 `capture --shots gate_approach,mound_block,grass_close,xiaoxiang` → `manifest-diff --baseline`。超 ±3% 不是错，**沉默和错归因才是错**：按视锥逐类数三角（§5 第 3 条），确认是买的细节再抬线，`--write-baseline` 三次连拍取中位数、`history` 记一行、`frameCostMs` 手工补（工具缺陷，§19）。
4. `manifest-diff --coverage`：覆盖率不降；野生件涨了就看是不是带 basis 的落位，是就抬 `coverage-baseline.json` 并写理由。
5. 判据表逐行量：需求文档 §7 / 单子验收表里的每一个数，用它指定的工具当场量（`tree-census --json`、`check:experience` 打印、pixel-diff）。
6. 图：单子指定的机位 + 贴脸机位 + **验收人自己加的临时机位**（用户提的病往往在没人拍过的角度——`gate_face` 之前十四轮没人拍过门内北望）。前后同机位同参数。
7. 文件域：`git diff --stat` 对单子头部；`tools/shot-list.mjs` 与机位归验收人，agent 动了就退回。
8. 判断题：agent 停在哪、给了什么选项；验收人裁或者转给用户。
9. 写 §N：判据表（目标 / 实测 / 结果）、抬线归因、判断、发现清单、结论一句。
10. 六处记账（§2 第 6 条），`git add` 只按路径，一次提交。

## 5 站住了的经验（每条都付过学费）

1. **自报不可信，数字从工具来。** 三次被自报骗过（§1）。验收人量到的数才进文档；agent 写现状列也只许写工具输出。
2. **没有一页纸把门、人、轴、峰、树放在一起，就没人看得出错。** `scenes/cuizhang.json` 说「主组是进门第一眼正对的」，plan 说门轴 x=55，主组在 x=8，三条体验断言全绿——因为它们测的是土山多边形不是石头。→ `D-29` 景需求文档。
3. **归因要 A/B，不要推理。** 三角涨了，按视锥逐类数（合批件 / 树 / 灌木 / 草）前后各一份再 diff；agent 的"看得更深"与实测相反。归因错了，基线就抬错。
4. **局部改动在散布里不是局部的。** Bridson 泊松改一处密度全园重洗（`P-28`）。改任何散布密度前先 dump 实例位置，合回后 diff。
5. **视张角决定工艺**（`D-27`）：台矶 32 px 上 4 mm 浮雕看不见，檐下漫射光里几何浮雕输给法线贴图（`P-26`）。做细节先算它在判据机位上占几个像素。
6. **原文几乎每次都站在用户这边。** 灯笼小气 → 「兩溜高照」；翠 → 「苔蘚成斑，藤蘿掩映」不是树；门钉 → 「並無朱粉塗飾」。用户提观感，先回原文找依据，再决定做法。
7. **机位是判据的一部分，归验收人。** 机位无自检门，十四轮没拍到匾（AT 发现）；AV 的判断题是「主组挪走后 `mound_block` 看到什么」，agent 拍图，验收人决定动不动机位。
8. **先立骨再穿衣。** 翠嶂 AV 的顺序是轴线 → 石脚 → 树 → 绿。反过来做，绿会盖住骨的错。
9. **拍图时别改源码。** vite HMR 会让正在跑的 capture 崩（`P-29`）。改 md 可以，改 ts / json 不行。
10. **worktree 的交付物合回前拷到主检出 `shots/<编号>/`**，worktree 一删图就没了（AN1 重拍过一次）。
11. **端口 `--strictPort`，别人的服务别用。** 5173 被人关过；旧 worktree 起的 5179 服务的是旧代码。
12. **观感迭代期不加门，冻结后再焊**（`D-28`）：正门四轮里没加形制断言门，冻结之后 AE 才能焊。门焊早了会把坏形态焊死。
13. **用户看不出的档位验收人定，看得出的问用户。** 颗粒 / AO 半径 / 灯身高——定；抱鼓石位置 / 匾宽 / 门钉有无 / 树的量级 / 地表改苔——问。问的时候给选项和代价，不给"你觉得呢"。
14. **冻结要有日期和范围。** 正门 `D-28`：冻结后只收台账 bug、形制断言门、用户点头的单项。没有冻结，边际最低的地方会一直吃预算。
