# 大观园 路线图

MVP(2026-09-10)验证了三件事:程序化的表现力、《营造法式》推导链的威力、零资产 3D 的可行。
之后按"造园"的方式补齐:先有图,再分区,基建与细节交错打磨。

## 0. 原则

- **平面图驱动**:`docs/plan/garden.plan.json` 是园子的真源。区域边界、路网、水系、景点、出处回目都在里面;
  装配器按区域读 `scenes/<区域>.json`,不再手写一张大表。
- **分而治之**:一个区域 = 一个可独立建设、独立验收(棚拍 + 区域截图 + 试玩)的单元 = 一个 agent 的并行任务。
- **原文最高,法式守底**:优先级栈见 ART_DIRECTION.md §1.5(原文 > 清式形制 > 法式结构 > 江南审美);大木作数字只从 `src/fashi/` 出,参数集按 tier 选;新建筑类型先补推导规则再出几何。
- **每一步可交付**:每加一区,游线延长一段,随时能上线试玩。

## 1. 平面图(进行中)

"忠实原著"的坑:文本自相矛盾,周汝昌、戴志昂、杨乃济、徐恭时等复原图彼此不同。
所以先定真源:workflow 综合学界复原方案当骨架,反驳者拿十七、十八回及后文原文逐条核,冲突记档。

产出:`docs/plan/` 研究稿(方案对比、证据表、冲突档)、`garden.plan.json`、可审的 `plan.svg`。

## 1.5 规模基建(分区开始前必做)

现在 60×60m 已是预算两倍;复原大观园约 300×300m,面积 25 倍。要做:

- 地形分块 + 区域流式装载/卸载;
- 远景 LOD / imposter(围墙、竹丛、树);
- 构件真实例化(同一变体多份只上传一次);
- 阴影范围随玩家滚动,而不是覆盖全园。

## 2. 分区建设(按原著游线)

潇湘馆(有雏形)→ 稻香村 → 蘅芜苑 → 省亲别墅牌坊/大观楼 → 怡红院 → 藕香榭/紫菱洲 → 栊翠庵 → 凸碧堂/凹晶馆。
每区一份 brief:边界、出入口、标高、建筑清单(法式 spec)、植物清单、原文出处。

## 3. 基建打磨(与 2 交错)

- 太湖石:皱更真、透孔更多、叠山成组;
- 植物:荷花、柳、梅、桃、芭蕉、松、海棠、藤蔓;
- 水:驳岸沿岸线自动摆、荷叶、倒影;
- 铺地:冰裂/鹅卵石/青砖花街;
- 推导器二期:`qing` 参数集(《工程做法》斗口制/举架/出檐,Tier A)与 `fayuan` 参数集(《营造法原》界/提栈/戗角/牌科,Tier B/C)接入,与 `fashi` 并列;真斗拱分件、转角、梁架、楼阁、牌坊。研究稿走 `docs/qingshi/`。

## 4. 细节打磨

对联与匾额书法、室内(家具、陈设、隔断)、灯笼、盆景、题字石。
