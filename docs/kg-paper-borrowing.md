# 同题论文调研：图谱语义驱动的大观园三维重塑

> 调研对象：魏仕龙、盛小俊、李敏敏等《图谱语义驱动的历史文化遗产三维空间重塑技术——以〈红楼梦〉大观园为例》，
> 《自然资源学报》2025, 40(12): 3507-3522，DOI 10.31497/zrzyxb.20251216。
> 单位：广东省人工智能与数字经济实验室（深圳）、深圳大学建筑与城市规划学院、自然资源部城市国土资源监测与仿真重点实验室。
> 调研日期：2026-09-10。**全文已通读，本文引用的数字与页码均出自 PDF 正文，非转述。**

同一个题目、同一批真源、不同的路。值得逐条对照，因为它把我们没走的那条路走完了，结果可以直接当参照系。

## 1. 他们的链

```
原文 + 建筑制式/园林法式 + 方位信息 + 山水 + 植物景观特征
    ↓ LLM + prompt 提示词
知识建模 → 开放关系抽取 → 三元组构建 → 数据清洗
    ↓
大观园领域知识图谱
    ↓
参数化建模生成 → 三维建筑信息库 → 山水高程建模 + 植物景观布置
    ↓
Lumion 仿真渲染 → 全景图 / 渲染图
```

另有一条与 3D 无关的支线：Stable Diffusion + LoRA 微调 + ControlNet 多通道控制（Canny 边缘、语义分割、线条、深度），生成"故事场景风貌图"，用来表达"宝钗戏蝶""宝黛共读"这类情节。那是 2D 出图，不是可走的场景。

**关键数字**（论文正文）：

| 项 | 数 |
|---|---|
| 知识图谱·地理方位部分 | 43 个建筑实体、51 条空间关系边 |
| 知识图谱·建筑构件部分 | **3505 个实体、3647 条关系边**（依据清《工程做法则例》） |
| 建模工具 | Rhino + Grasshopper（论文明说"与传统 BIM 方法相比，更注重细节还原与灵活设计"） |
| 分区方法 | PaddleNLP 古典中文词向量 + K-means 聚类，得四区 |
| 渲染 | Lumion |

**参数化建模的三层**（式 2）：柱网层 S、辅佐层 A、屋架层 R。

- 柱网层：柱数、柱距、柱径、柱高
- 辅佐层：斗口模数、层数、样式（斗口模数取清《营造法式》中相对应模数）
- 屋架层：举折比例、屋顶类型、瓦面样式、脊饰形式

这三层与我们 `builder/derive/` 的柱、铺作、举折三段是同构的。可以拿来交叉验证我们 `Frame` 的字段是否漏项。

## 2. 同与异

**同**：真源同一家族。他们表 3 直接引清《工程做法则例》第 35、36、90、92 页（墙身收分、庑殿顶脊饰构成、瓜柱尺寸、歇山顶形式）。我们的 `knowledge/docs/qingshi/` 挖的是同几本书。

**异，而且是根本的两条**：

### 2.1 他们的图谱记关系，我们的规则记算法

他们的三元组是"溜金斗 属于 斗拱""潇湘馆 位于 西南""瓦石 承载 台基"。
我们的规则是"举高 = L/3，出处卷五，公式可执行，两名核验者裁决通过"。

**他们的图谱不能算数，我们的规则能算数。** 他们的参数化建模是另写的 Grasshopper 脚本，图谱给的是"该有哪些构件、什么关系"，具体尺寸仍要人从书里取。

### 2.2 他们没有核验层

通读全文，没有出现任何"规则被驳倒""数值与实测对不上""此条存疑"的机制。LLM 抽出的三元组经"数据清洗"后直接进图谱。

而我们用同一批书挖出来的结论是：**推导性规则 133 条只有 71 条通过（53.4%）**，六章屋顶瓦作通过率仅 25%（16 条通过 4 条），驳倒 18 条。其中一条（05-06「个」的读法）照抄会把屋面抬高一倍。

**这里要克制推论**（2026-09-10 自审收窄）：我们那 133 条是**推导性规则**，他们那 3505 条是
**构件实体**，两者不是同一总体，不能拿 53.4% 的通过率去推他们的错误率。能说的只有这一句：

> 同源古籍里的推导规则一经核验就暴露出大量歧义与错误，那么未经同等级核验的 3505 个实体
> 就不能默认可信，只能当**候选本体清单**而不是真源。

这不是指责——他们的目标是"在数据不完备条件下做空间重塑"，核验不在其研究问题内。
但对我们意味着：**要用它的构件清单可以，要取它的尺寸必须自己回书核。**

一个佐证：他们的 K-means 分区结果里，沁芳闸桥被聚进翠意幽径区，与地理位置矛盾，论文自陈"故对聚类结果进行局部调整，将沁芳闸桥划归至禅意祈福区"。语义相似不等于空间相邻。我们的分区走的是原文空间证据加判决书裁决（`knowledge/docs/plan/04-conflicts.md` 28 条），不是聚类。

## 3. "他们的建筑看起来更丰富"——拆开看

用户肉眼判断他们的建筑丰富度更好。这个判断成立，但成因要分三份，只有第一份是我们该补的。

### 3.1 真差距：构件粒度（该补）

3505 个构件实体带形制描述（表 4 举例："溜金斗——一种特殊的斗栱。自中线以外，与普通斗栱完全相同。中线以里，自要头以上，连撑头与桁碗，都在后面特别加长，顺着举架的角度向上斜起秤杆…"）。

我们现在的铺作是几个倒角箱体摞起来的示意，`builder/parts/damu/building.ts` 里的 `placeSet` 就是栌斗加华栱加令栱三件套。

**这是实打实的差距**，而且正好是清式批评稿 A 系列点名缺的东西（缺铺作三维叠层与里跳、缺替木衬方头、缺转角列栱）。

### 3.2 渲染差异（不是丰富度）

Lumion 是离线建筑可视化渲染器，一帧可以算几分钟，自带材质库、全局光照、真实天空。我们是浏览器实时 WebGL，预算 260 draw calls、60fps。

他们的静态图不需要碰撞、不需要帧率、不需要 draw call 预算。**把这个差异算进"建筑丰富度"是错误归因。**

### 3.3 风格差异（不是质量差异）

他们是清官式：红柱、绿窗、彩画、脊饰吻兽（图 6 的怡红院"整体建筑以大红色为主，并辅以绿色窗围"）。

我们按 `ART_DIRECTION.md` 定的江南文人园林：粉墙、黛瓦、栗色木作，苏式不用朱红金黄的官式彩画。

红绿彩画确实更"热闹"。**但这是我们主动选的，2026-09-10 复核后维持不变。** 理由在 `docs/DECISIONS.md` D-05 与 D-06：大观园有两套建筑语言，省亲主轴（Tier A）要贵、正、礼，一离开主轴就是明清文人园林。全按官式做出来是缩小版故宫。

我们的 Tier A（正门、牌坊、大观楼）本来就允许彩画——`knowledge/docs/qingshi/tiers.md` 的 R-05 裁决明确给正殿解禁金彩，并要求同步在艺术圣经色板补注例外。所以主轴的"热闹"我们会有，只是不铺满全园。

## 4. 结论

**该抄的一条**：**构件级本体**。我们的 `knowledge/rules/` 现在只到"规则"粒度（举高怎么算），没到"构件"粒度（斗拱由哪些分件构成、每件什么形状、怎么连接）。补上这一层，几何丰富度会直接跟上。落点见 `docs/ROADMAP.md` 的 P1 与 P3。

**可交叉验证的一条**：他们的柱网层、辅佐层、屋架层三层参数表，可以拿来核对我们 `Frame` 的字段是否漏项。

**不该抄的三条**：

1. **LLM 直抽三元组不核验**。我们 D-04 明确否过这条路，理由是单 agent 报告会把编造当事实，而且看起来很硬。他们 3505 个实体的可信度未知。
2. **Rhino + Grasshopper**。离线建模工具，进不了浏览器，与"可走的园子"这个目标不兼容。
3. **SDM 出图支线**。那是宣传图不是场景。我们要的是能走进去的园子。

**保持不变的一条**：江南风。他们更偏清官式所以"更热闹"，这是风格选择不是质量差距，2026-09-10 复核后维持。
