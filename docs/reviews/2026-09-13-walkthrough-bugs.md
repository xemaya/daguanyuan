# 2026-09-13 试玩反馈：七条

用户在 PQ 几何半（N/O/P/Q）全部合入后走了一遍，提出七条。
下面每条分两段：**用户说的**（原话意思）与**我核到的**（代码/数字/截图，或"未核，是判断题"）。

排期上这七条**不阻塞 WG**——WG 是渲染层迁移，与这里的几何、数据、UI 问题不重叠。
但 **⑥ 的两半有一半属于 WG3 的后期重建**，见下。

## ① 植物看着还是旧的，"像假发片"

**用户**：植物没怎么换，质感还是假发片。

**我核到的**：树种**确实换了**——`SPECIES` 现在是 `elm`（榆）/ `locust`（槐）/
`pine-old`（古松）/ `cypress` / `willow`（柳）/ `pear`（梨）/ `peach`（桃）/ `haitang`（海棠），
橡树白桦已清。所以换的是**品种参数**，没换的是**树冠的做法**——树冠仍然是
`count: Math.round(150 + cR*cR*...)` 张**交叉卡片**，走近了就是一片片穿插的平面，
这正是"假发片"。

**单子 O 没做错**：它的范围写死了"只改几何、品种、散布，**不改着色**"，而卡片树冠
既是几何也是着色（alpha 裁切 + 透叶）。**树冠的做法要等 WG 之后**（`foliage-materials.ts`
的 shader 注入段是 WG2 的移植目标）。

**落点**：PQ 着色半（WG 之后）。归 `ROADMAP §PQ-5`。

## ② 潇湘馆不该用虎皮石

**用户**：大门用虎皮石 OK，潇湘馆不该用。

**我核到的**：**用户是对的，而且这是原文问题不是审美问题。**
`07-02` 的原文是「**左右一望**，皆雪白粉牆，下面虎皮石，隨勢砌去」——
「左右一望」说的是**正门左右的园墙**。潇湘馆的是「**忽抬頭看見前面一帶粉垣**」（`07-07`），
只说粉垣，没说虎皮石。

而单子 Q 的注释写着「全园每一段粉墙都吃到，**不分 kind**」——**是我在单子里写死的**
（"这是全园粉墙的墙基，不只正门……别只改正门那几段"）。**单子写错了，Q 照做没错。**

**落点**：虎皮石按**墙的种类**分——园墙（外围、正门左右）用，院墙（潇湘馆粉垣）不用。

## ③ 进门前"地铁轨道"通向天际

**用户**：进门前有个 bug，修出地铁轨道来了，通向了天际。

**我核到的**：**确认，截图在 `shots/bug/spawn_right.png`。**
两条平行的深色**路牙**夹一条铺装带，一直伸到地平线。

根因：**路牙沿 `plan.json` 的路径折线整条挤出，没有按地形窗口裁剪**。
路径折线覆盖整个 500 m 园子，而地形只有 280×226 m 的窗口；
窗口外没有地形，路牙就飘在空里一路延伸。

加重它的两件：铺装是**大块平板**不是石子漫（见 N 验收时已记的判断题），
路牙是一条**硬直的深色线**——两者叠起来正好读成轨道。

**落点**：路牙与铺装都要按 `TERRAIN` 的窗口裁剪；窗口边缘要淡出，不能硬切。

## ④ 匾额：字序、字体、太素

**用户**：牌匾的字应按古代格式**从右向左**；字体不够古意，太现代；牌匾有点素，后面要优化。

**我核到的**：
- **字序确实是从左到右**：`builder/parts/xiaomu/plaque.ts:27` 是
  `for (let i = 0; i < n; i++) g.fillText(text[i], x0 + i * gap, ...)`。**是 bug。**
- **字体声明的其实是楷体**：`g.font = 'bold ${size}px "STKaiti","KaiTi","Kaiti SC","Noto Serif SC","Songti SC",serif'`。
  但渲染出来是黑体感——**说明这串字体名在 canvas 里没命中，落到了兜底**。
  要查是名字不对（macOS 上是"STKaiti"还是"华文楷体"）还是 canvas 取字体的时机问题。
  **别直接换字体名了事，先确认命中与否**，否则换一个还是不命中。
- **太素**：匾现在是黑底 + 金字 + 一圈金线。真匾有边框线脚、有落款。**这条是判断题，
  不是 bug**，归 P5 细节。

## ⑤ 潇湘馆的竹子种到房间里了

**用户**：潇湘馆竹子种到房间里面了。

**我核到的**：**确认，而且能给出坐标。** `composer.ts` 摆的七丛竹里有两丛落在正房里：

```
grove (-100.2, 101.0)   ← 正房 footprint 中心(-105, 99) 半宽 6.8 / 半深 4.8
clump (-109.8, 103.0)
```

根因：竹子坐标是**旧世界坐标整体平移**过来的（`D_XIAOXIANG = [-114.4, 118.6]`，
按旧正房 (9.4, −20.6) → 新锚点 (−105, 98) 标定）。房子后来被单子 M 与 P 改过
（加了台基与踏跺），**平移量没跟着更新**。

**这正是 `missing` 的 `99-25` 应验**：footprint 有两份真源，而
**composer 摆的构件根本不过 `FOOTPRINTS` 检查**——那张表只管散布器。

**落点**：短期把这七丛按新几何重摆；真修法是 `99-25` 的 occupancy prepass（P4）。

## ⑥ 走五分钟电脑发烫、有点晕 3D

**用户**：走 5 分钟电脑开始发烫，而且有点晕 3D，应该是步行视角不稳 + 远处失焦。

**我核到的**：三个独立成因，**分属两期**：

| | 现状 | 落点 |
|---|---|---|
| **远处失焦** | `dofFar: 220`，即 `smoothstep(99, 220, d)`——**99 米就开始虚，150 米已虚 42%** | 第一人称漫游里这个太早。**WG3 重建后期链时一并定**，别现在调（调完 WG 还要再调一遍） |
| **步行视角不稳** | `PlayerController` 有按里程驱动的 head bob | 与 WG 无关，**可以现在改**：给幅度一个上限或加开关 |
| **发烫** | 14 镜 79–186 fps，没有帧率封顶 | 满帧跑就一直烧 GPU。**加一个帧率上限**（60 或跟随显示器），与 WG 无关 |

**注意"晕"未必只是这三条**——视场角、移动加速度曲线都可能有份，**这是判断题，
改完要让用户再走一遍确认，不能只看数字**。

## ⑦ 地图能开但鼠标点不了

**用户**：M 能开地图但鼠标不能点；按 Esc 露出光标，但马上弹出菜单。

**我核到的**：**是我写的 bug。** `projects/daguanyuan/main.ts:124`：

```ts
container.addEventListener('click', () => {
  engine.input.requestLock();   // ← 无条件请求指针锁
  audio.unlock();
});
```

地图开着时点它，事件冒泡到 container，**又把指针锁抢回去了**，光标当场消失。
按 Esc 释放锁 → 引擎判定"失去锁"→ 弹开始卡。

**修法**：这个监听在地图可见时要跳过；开图时同时把开始卡的"失锁即弹"抑制掉。
一并复查 `99-27`（传送是调试便利，发布前收口）。
