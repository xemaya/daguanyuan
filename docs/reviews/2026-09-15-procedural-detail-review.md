# 程序化细节深化评审

日期：2026-09-15。范围：当前工程与四区 MVP；不使用 Blender，不修改运行时代码。

## 判断

现有技术足以把四区推进到“近看有工、走动有层次”。最值得投入的是构件的加工方式、表面信息的尺度、物体之间的接触关系，以及不同观察距离下的表示方式。

从代码和本轮实拍看，部分新增细节仍会读成圆管、球、盒子和噪声。下一步应把程序的输入从“形状参数”推进到“这块材料如何加工、怎样装配、在什么环境里”。保留动森式的柔和大形，给近处明确的工艺信息。

## 3. 第一优先级：让已有细节被正确看见

### 3.1 表面坐标：石头不应长出木纹，墙脚不应随贴图循环

`baogushi.ts:32` 的鼓形使用 LatheGeometry，直接沿用旋转体 UV；叠加 `whiteStoneMaps()` 的方向性凿痕，在端面产生本轮看见的放射状纹理。

建议：

- 鼓面采用局部平面投影，鼓帮采用沿圆周展开的坐标；颜色、法线与粗糙度一起改映射。
- 木件按实际长轴生成纹理坐标，端面单独表达；梁、柱、门板不要只套同一种 UV 方向。
- 在材质配方中明确纹理覆盖多少米、凹凸高度多少毫米，避免一个纹理 repeat 同时承担尺度和强度。
- 不规则石头可沿用/完善现有投影方案，必要时用三平面投影；法线必须做对应的方向变换，不能只混三份 RGB。
- `plasterMaps()` 把潮痕烘在可重复的 v 坐标中。把“材料微纹理”与“离墙脚的真实高度”拆开；后者由构件局部高度、地形高度和环境遮罩控制。潇湘馆墙面的色带需要分项排查，不能仅凭截图认定全由此造成。

### 3.2 清晰度对照

本轮暗部存在显眼的全屏颗粒；`PostFX.settings.grain=0.016`，grade 在最终 sRGB 转换之前加颗粒，暗部感知对比可能被放大。

先在同一机位分别比较颗粒 0 / 原值、AO 关 / 开、材质法线弱 / 原值。找出哪一层遮住雕刻。保留最终输出抖动作为独立机制，不把所有噪声一次性关闭。不要同时调曝光和全部材质，否则无法定位收益。

这一步不是“加新特效”，但可能是最快让现有斗拱、雕刻变清楚的办法。

## 4. 第二优先级：把“装饰线”升级为“雕刻面”

### 4.1 推荐的程序化雕饰工具

现状：`makeGeshan()` 的绦环板用一条管和几枚压扁球；台基卷草使用 TubeGeometry，且在 `forecourt-terrace.ts` 复制了一份。曲线已经有回转，但圆管截面仍容易读成粘上的铁丝。

建议共用一份**二维纹样描述**：主藤路径、卷叶封闭轮廓、分叉、边界、留白。由它生成两种输出：

1. **近景几何**：主藤宽度沿路径变化；叶片有宽面、主脉与收尖；纹样边缘缓缓落回石面。用有厚度的扁截面扫掠、带倒角的轮廓挤出，或高度场网格生成。
2. **中景贴图**：同一纹样烘出高度、法线与凹槽遮蔽；远处只保留窄带的整体明暗和边缘。

单层浅浮雕非常适合 `h(u,v)` 高度场：曲线距离给出主藤，封闭叶形给出叶面，分区设高低，再对边界做平滑过渡。穿透洞、倒扣、独立突出轮廓继续用真实几何；高度场无法表达这些。

**最值得做的样件是一小段西番草石雕。** 正面能读叶面，斜看能读浮起，侧光能读凹槽；三者通过后再铺到台基，不先扩展图案数量。

此项接续现有 C4；不与 AJ1 的砌缝修整混成一次观感对照。具体纹样的史料状态沿用知识库，新增形式记 `provenance.art`。

### 4.2 屋檐与小木的截面库

把梁枋线脚、门框起线、裙板压边、阶条石、瓦口收边，抽成少量可复用截面。二维截面沿路径扫掠，比大量盒子相互压叠更容易获得连续的高光和阴影。

- 真几何优先投给檐口外轮廓、门洞边、窗棂、台阶鼻口和人能走近的转角。
- 屋面大部分继续靠瓦纹；可近看的檐口前几排增加搭接厚度，远屋顶保持轻量。
- 倒角尺寸按构件层级分：柱础和石阶可以明显，细棂条应极细；轮廓采样按曲率与屏幕误差增加，避免所有小件一起提高细分。
- 风格圣经的“最小 1.5cm 倒角”与当前 2cm 棂条需要建立明确的小木例外，否则细件会圆成胶条。

### 4.3 窗花：共享纹样描述，专门生成窗棂与漏窗

用户补充：窗花现在也很粗糙，应与上述细节深化一起处理。**将正门的一扇灯笼锦窗列为第四个样板。**

现有窗棂已有真实几何。下一轮优先改善比例、截面、交接和深度，不以增加线条数量作为精致度指标。代码入口是 `builder/parts/damu/building.ts` 的 `makeGeshan()`、`lanternLatticeGeometry()`，以及 `builder/parts/qiangyuan/wall.ts` 的格心生成逻辑。本轮斜视截图可见厚度，但尚缺格心正面和背光专项对照，不能把以下改进方向全部当作已定位的缺陷。

| 层次 | 程序化做法 | 观感目标 |
|---|---|---|
| 纹样比例 | 控制主纹、辅纹、空隙与边框比例；完整单元在边界有明确收头规则 | 正面有秩序，疏密清楚，边缘没有随意切断的半个花样 |
| 棂条截面 | 主框、内框、细棂分粗细；细棂使用小倒角，按样式选择轻微起线 | 斜看能读木条厚度与细高光，不呈统一粗方条或圆胶条 |
| 交接节点 | 先求线网交点、拆分边、合并重合段，再按节点类型裁切和连接 | 交叉处不鼓包、不重复叠面，转角连续、收头贴合 |
| 前后层次 | 外框、内框、格心、纸面分别设深度；纸面退后，框边产生遮光 | 细阴影说明装配关系，窗纸不与棂条挤在同一平面 |

建议生成链：

> 纹样规则 → 二维线网与封闭轮廓 → 边界收头与节点整理 → 截面扫掠／带孔挤出 → 距离分级。

同一份二维纹样描述可派生三类输出：窗棂生成有厚度的杆件网络；漏窗生成带真实孔洞的连续窗芯；裙板雕花生成浅浮雕。共享轮廓、比例与采样工具，几何生成器各自处理本类对象的结构。规则型纹样保持对称和周期秩序；冰裂纹的变化也需约束最小空隙、边界连接和过密节点，不能靠随机线条代替设计。

**法线贴图不能代替窗洞。** 近景必须保留真实厚度和开口。糊纸窗中距可以试验把细棂烘到含纸面的表示上，但需要保持框架与主要阴影；透景漏窗则应保留主孔洞，只简化截面细分和次要纹样。若试用透明裁切的远景表示，要单独验证侧视、背面、投影和锯齿，不能直接套用浅浮雕的远景方案。

第一件保持现有灯笼锦花样和窗洞尺寸，集中改变棂条截面、节点、收头与纸面深度。不要同时换图案，否则无法判断工艺提升的收益。材质沿构件长轴取向，重复窗扇共享原型；新属性与细节档按第 8 节保留至装配末端。具体接合形制和纹样历史依据继续走知识库，未有依据的实现明确记为艺术选择。

验收交付：

- **正面**：完整纹样、边界收头、主辅比例与留白可读。
- **斜面**：棂条截面、节点厚度、纸面退后可读，无穿插和共面闪烁。
- **背光或透景**：糊纸窗检查框边遮光，漏窗检查真实景物穿过孔洞和投影；不靠添加构件私灯制造效果。
- **装回正门的中景与走近片段**：细节不抢整座门的体量，远处不糊成噪点，距离切换不突变。
- **预算**：记录单扇几何、重复装配后的提交和阴影成本；高质量样件不以每根棂条独立 draw call 的形式铺满全园。

## 5. 第三优先级：材质表达加工方式

目前白石和青石基本共享同类凿痕逻辑。色差已经有了，但工艺差异还有很大空间。

| 对象 | 程序化配方应表达什么 | 最值得控制的通道 |
|---|---|---|
| 白石鼓面 | 细磨面、弱颗粒，鼓帮和座脚略粗 | 低幅法线、粗糙度 |
| 青石踏面 | 大面平整、边缘轻微圆磨、细小局部变化 | 接缝、边缘几何、粗糙度 |
| 粉墙 | 宽而浅的抹灰起伏、轻微砂感 | 低频法线、低对比色差 |
| 木作 | 长轴木理、端面差异、薄漆；大部分平整 | 方向坐标、粗糙度、适量 clearcoat |
| 黛瓦 | 按片的小色差、搭接阴面、受潮位置 | 片 ID、接缝、湿度遮罩 |
| 窗纸/灯纸 | 细纤维与厚度变化，框边遮光 | 透光遮罩、低对比纹理 |

每种材质分三档信息：米级的整体色块、厘米级的加工/拼接、毫米级的微表面。现在应重点补厘米层，并收敛远处过密的高频噪声。

老化要克制：贵族园林可以有湿润和使用痕迹，不应默认满墙裂缝、严重剥漆、到处碎瓦。

## 6. 第四优先级：让细节之间有因果关系

在现有草被/露土共享场的基础上，增加几项简单可烘焙场：距岸距离、距墙脚距离、遮蔽程度、路径使用强度、树种覆盖。无需真实水文或通用求解器。

例子：

- 背阴墙脚：淡潮痕 → 薄苔 → 石缝小草；三者在同一片位置上发生。
- 台阶中间：清洁、轻微磨光；两侧：少量积尘/落叶，保持通行面明确。
- 竹丛下：竹叶、薄腐殖层、偶露根部；普通树下按其树种落叶，不混成一套通用杂物。
- 岸边：低处湿石、缝中细草、水线少量水生植物；变化沿岸线成段出现，保留干净水面。

在 `parts` 输出墙脚、檐口、踏步边、水接触边等少量语义锚点，`compose` 按规则附着细节。优先延续当前 scene/style 规则，不把坐标写回某个巨型场景函数。

`intentional_void` 目前还没有在 builder 中落地消费；新增散布应同步接入留白排除区。增加密度前先保证可以明确“不生成”。

## 7. 植物与水的深化顺序

### 植物

已有共同风场和叶片透光，继续增加球团或叶片数量的收益有限。下一步应增加树种之间的枝序、叶簇方向、枝下空隙和冠缘疏密差异。

- 远处保留成片树冠的简洁体积。
- 中距让枝干与叶团之间有可见空隙。
- 人行路径附近才出现清楚的小枝、竹节、叶簇和少量叶片卷曲。
- 微风按主枝、小枝、叶簇分幅度和相位；仍由一个空间风场驱动，不让每片叶子独立乱抖。
- 少量飘叶、灯笼轻摆、偶发水纹作为视线中的事件，限定数量和位置；本轮静帧没有验证运动效果。

### 水

当前已有流向、深浅、岸缘、波纹和焦散近似，不缺“水在动”的基础。贴水视角中亮线和表面纹理密度较高，先校准纹理尺度、对比和掠射角衰减。

之后可做一处低分辨率平面反射实验：优先反射亭、桥和大树，排除细草/微小装饰，关闭递归反射，由波纹打散倒影。起步分辨率比例可试 0.25/0.5，但这只是实验参数，不是已验证预算。

本地 Three 0.185.1 已含 ReflectorNode；官方提供 `resolutionScale`、`generateMipmaps`、`bounces`。接入当前自定义水节点仍需要设计与实测，不能直接承诺“加一个节点就完成”。平面反射会多渲染一遍选中的场景，降低分辨率并不能免掉几何提交。

这项放在局部几何优化之后，不作为首轮主线。

## 8. 管线需要先补的两处

### 8.1 保留语义，再实例化与合批

当前链：`buildBuilding()` 在 `building.ts:1619` 先 `mergeByMaterial(root)`，之后 `composer` 才 `assembleStatic()`。因此部分重复的窗扇/雕饰到实例化阶段已经被打散合入大网格；不应假设新增小件会自动享受实例化。

同时，`merge.ts:23–25` 只保留 position/normal/uv/color，新增的湿度、凹槽、部件 ID、第二套 UV 等属性会被删除。

建议有限调整：

- 可重复小件输出共享 geometry/material 引用及 placement；先实例化，再合并剩余静态件。
- 合并键纳入属性布局、细节档和阴影策略；缺少属性时明确补默认值或分桶。
- 保留 `surfaceId`、`prototypeId`、语义锚点等必要信息；不为每一块石头 clone 一个材质。
- 雕饰和主体分组，才能单独切换距离档；不要为整栋房子一次性复制三套完整模型。
- 碰撞/可行走表面继续来自稳定结构数据，不随画面 LOD 改变。

InstancedMesh 降低重复对象的提交成本，但不会消除每个实例的顶点工作。它与细节分级需要配合。

### 8.2 同一份细节描述，生成近中远三种表示

建议从台基雕饰试点：

| 观察条件 | 表示 |
|---|---|
| 贴近、斜看、影响轮廓 | 真实浅浮雕几何与边缘 |
| 中距、轮廓已不可分辨 | 同源法线/粗糙度/局部遮蔽贴图 |
| 远处、纹样低于可读像素 | 主体与窄带色调 |

按屏幕尺寸决定档位，并用滞回避免走动时反复跳档。近中档过渡要保持整体明暗；若用抖动渐变，还需测试本项目无完整 TAA 时的颗粒和闪烁。

更细的纹样继续通过现有 Worker 烘焙，不在每帧重算复杂距离场。先补缓存键：配方版本、seed、尺寸、分辨率、细节档。现有若干纹理 key 没包含 size，直接新增多分辨率调用会命中同一个缓存结果。

如需缩短重复启动，可增加版本化的浏览器持久缓存；缓存可丢弃，源头仍完全由程序生成。无需引入手工模型或外购贴图。

## 9. 推荐执行顺序

1. **正门样件对照**：鼓面坐标修正 + 白石加工尺度；保持结构不动。另做颗粒/AO 的单变量对照。
2. **接续 AJ 的构件收口**：台矶分块与排缝、抱鼓石形体、瓦口盖缝；与后续雕饰重做分开验收。
3. **一段雕刻升级**：同一个西番草纹样，产近景几何与中景法线两个版本；先证明质量与预算。
4. **一扇窗花精修**：保留正门现有灯笼锦花样，改善比例、棂条截面、节点收头与纸面深度；交正面、斜面和背光对照。复用雕饰的二维纹样工具，窗棂与透景开口采用专门的几何表示。
5. **最小管线调整**：让上述样件的实例化、属性、LOD 能走完整条 compose 链，再推广到更多窗扇/线脚；局部样件阶段就明确属性和原型契约，避免完成后返工。
6. **一个接触区样板**：潇湘馆墙脚—石基—竹丛，统一潮痕、苔、落叶；检验留白和路径不被覆盖。
7. **水边与植物动作**：先岸线/波纹尺度，再选一个池面验证倒影成本。

每轮交付同机位 A/B：近处正视、近处斜视、中景、短距离走近/退远。新加的细节必须在图中可读；运动不闪、接缝不穿、远处不糊成噪点。性能记录分开写主场景、阴影、后期/反射提交及帧时间；重新建立独占 GPU 的基线后再设增量上限。

## 10. 技术边界与资料

程序化特别适合营造模数、截面扫掠、格心纹样、浅浮雕、砌缝、植物枝序和语义散布。复杂人物、深倒扣兽面、需要逐刀塑形的自由雕塑仍然难；现阶段不必用这些高成本对象证明程序化能力。

法线贴图改变表面受光，不改变真实轮廓、透孔和几何遮挡；轮廓明显的部位仍需几何。参见 [Three.js MeshStandardMaterial](https://threejs.org/docs/pages/MeshStandardMaterial.html)。

实例化与平面反射能力参见 [InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html)、[ReflectorNode](https://threejs.org/docs/pages/ReflectorNode.html)；接口同时对照了本地安装版本。

**首个目标：让一块白石、一段雕花、一扇窗花、一处墙脚，经得起走近看。四个样板形成共享配方后，再把能力铺开到全园。**
