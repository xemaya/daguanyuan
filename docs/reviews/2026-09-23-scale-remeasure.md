## 判断

1. **「15 fps 不可玩」已经过时**。现在 19 区是 41–43 fps，AQ-c 和 AV-b 把大头收回来了。ROADMAP 第 9 项的数改成这次的读数。
2. 病根是三个**只跟面积有关**的成本：远处地形、随簇数涨的建时、远处的亚像素小件。它们与区里建了什么无关，**现在就能治，不用等 P4**。
3. 区级流式和 HLOD **暂不做**：要真建好的区才能验收，空桩区给不出可比的东西。触发条件写在 AX 单子末尾。
4. 用户问「是不是 WebGL / 引擎的问题」：**不是**。现在跑在 WebGPU 上（metal-3），700 万三角主场景只花 4.5 ms GPU；
   缺的是地形 LOD、按屏幕尺寸剔除这类标准手段。58 s 建时来自运行时程序化生成，是这个项目自己的设计选择，与图形 API 无关。

## 顺带发现

- **`xiaoxiang` 4 区三角 3.75M，比 `perf-baseline.json` 的 3.145M 高了 19%**（draw call 247 vs 251，在容差内）。时间上对得上 AL1–AL4 合回，要在 AL 验收里归因、抬线。AX 必须等这一步做完再派。

## AX1 · 地形分档

**做法**:每块 64 m 地形建四档,步长 1 / 2 / 4 / 8 格(0.48 / 0.96 / 1.92 / 3.84 m)。粗档**与 L0 共用同一份顶点缓冲,只换索引**,
所以粗档的顶点就是 L0 格点、高度与法线逐位相同(测试断言)。四档是四个 Mesh,同时只有一个 `visible`,
选档挂在 world tick(在 player-sys 之后,读到的是这一帧的相机),每帧不分配。阴影:地形只接影不投影,天然同一档。碰撞没动。

**接缝用缝合,不用裙边**:块边、以及格距不同的格之间的边,两侧都取 L0 的全部格点、扇形收进格内,构造上不裂
(测试断言块内每条内边恰被两个三角共用、块边每段 L0 小边恰一个)。不用裙边:要往顶点缓冲里追加顶点(L0 就得变、粗档不能共用缓冲),
窗口外沿一圈裙边会露在海面上。代价是每块边上约 4×133 个细长三角。

**误差预算(单子没写的一步,要验收人看)**:第一版按「整块最大误差」选档,园里但凡带一段驳岸、台基边的块,L1 误差就到 1.3~2.1 m,
永远切不下去(4 区地形只降 28~46%)。改成:每档有误差预算 = 一格边长 / 16(0.06 / 0.12 / 0.24 m),超预算的粗格格距逐级减半
(8→4→2→1),只钉住陡坎那几格。**切档仍按每块每档量出来的最大误差、投影 < 1 px 现算**,预算只决定粗档多早能接管。
试过另外 7 组预算(0.04~0.10 / 0.08~0.20 / 0.16~0.54),19 区 `gate_approach` 地形都不比这一组少。
