# 决策记录

每条决定：**为什么这么定、代价是什么、什么情况下该推翻**。

写这份文档是因为理由本来散在 spec、路线图、commit message 和对话里，下一个人会把它们重新辩论一遍。有代价的决定尤其要记——只写结论不写代价的记录，会让后来者以为这是免费的。

## D-15 维持江南风，不因同题工作"更热闹"而改清官式

**定于** 2026-09-10（读同题论文后复核）

同题的《自然资源学报》论文走清官式：红柱、绿窗、彩画、脊饰吻兽，画面明显更热闹。
复核后**维持江南**：粉墙、黛瓦、栗色木作，苏式不用朱红金黄的官式彩画。

**理由**：这是风格选择不是质量差距。大观园有两套建筑语言（见 D-06），全按官式做出来是
缩小版故宫。我们的 Tier A（正门、牌坊、大观楼）本来就允许彩画——`tiers.md` 的 R-05 裁决
已给正殿解禁金彩，所以主轴的"热闹"我们会有，只是不铺满全园。

**代价**：整体画面比清官式路线素。这是有意的。

**同时确认的一条真差距**：他们的建筑构件知识图谱有 3505 个实体，我们的铺作是三个倒角
箱体摞起来。这个要补，落点见 `docs/ROADMAP.md` 的 P1 构件级本体与 P3 真斗拱分件。
完整对照见 `docs/kg-paper-borrowing.md`。

## D-12 载入页徽标用月洞门，不用别的

**定于** 2026-09-10

原来是继承自真新镇的精灵球。换成月洞门：它是江南园林的签名元素，是圆的（同样的画面占位），而且园子里本来就有这个构件，徽标与实物同源。

**代价**：72px 上放不下细节。试过在洞里加竹影，4 倍放大读成两道刮痕，删了。最终只靠四层明度差（粉墙 → 青石门套 → 洞里的绿 → 洞底日光地面）。

## D-13 体积云与天光自己写，不引地球尺度的库

**定于** 2026-09-10

项目最初被 tellux 吸引，是因为它的云和阳光好看。但 `@takram/three-atmosphere` 与
`@takram/three-clouds` 按地球尺度设计（球体、ECEF、太空视角），我们是园林尺度，
天空穹顶加 FogExp2 才是对的。

**观感目标保留，实现路子换掉**：局部天气图加两张 3D 噪声加蓝噪声抖动加云影，
园林尺度自己写够得着。排期见 `docs/ROADMAP.md` §3.5。

**代价**：得自己写一遍，没有现成的。

## D-14 不做昼夜，只做白天的光影变化

**定于** 2026-09-10

时刻固定在艺术圣经 §1 的晴天上午（太阳高度角约 38°）。要的是**光影变化**，不是时间流逝：
云影缓慢掠过地面、树影随风轻晃、水面反光随视角走、远景随距离叠天空色。

**这条决定省掉了一整块基建**：昼夜需要单一时间源（天空、水面、风、音频都从它取时间，
否则一改就漂），那是 tellux 调研建议的第一步。不做昼夜，这块基建就不必建。

**代价**：没有晨昏与夜景。真要加，得先补时间源，而且那时候现有的水面与风各自持有的时间
都要收编——越晚做越贵。

## D-11 观感回归用结构数字，不用逐像素

**定于** 2026-09-10，执行 P0 Task 1/2 时实测推翻了原计划

原计划写的是"纯重构应逐像素归零"。实测不成立：场景里水面、竹叶、云一直在动，同一份构建连拍两次，平均每像素差 7 到 17 个色阶，`treeline` 有 23% 的像素差超过 24 阶。相机不是原因——截图工具每次 teleport 到写死的坐标与朝向，对照实验里两次之间相机完全没变。

改为比 `manifest.json` 的 draw calls、三角数、几何数、材质数。这四项是场景图的函数，确定性的。

**证据**：搬家时构件登记的 glob 落空，全部构件静默消失，正是被 draw calls 从 180 掉到 80 抓出来的；逐像素反而淹在噪声里。

**代价**：结构数字管不了"东西还在但变丑了"。观感回归靠 `tools/side-by-side.mjs` 出左右对照交人眼。

**什么时候推翻**：如果给引擎加了冻帧钩子（把动画时钟钉在固定时刻），逐像素就重新可用，而且比结构数字锋利得多。

## D-10 分层：engine / knowledge / builder / projects

**定于** 2026-09-10

目标是圆明园能复用。`builder/` 不认识大观园，给它平面数据和施工图它就能造园。

**代价**：一次性搬家，91 个文件变动。以及一条持续成本——跨层必须走别名、依赖只能自上而下，由 `check:layers` 强制。

**为什么不拆包**：现在只有一个使用者，每改一行引擎要发版本再升级，迭代期太痛。目录分层已经能卡住边界。将来真要开源引擎时再拆。

## D-09 知识库以 JSON 为真源，md 留作考据

**定于** 2026-09-10

`rules/*.json` 是代码唯一入口，研究稿 md 保留证据、引文与两名核验者的裁决。门只校验两者的**条目集合与状态**一致。

**为什么门不校验数值**：研究稿是 agent 写的散文，公式与表格格式不稳，自动抽取器会很脆，而且会给出虚假的安全感——门绿了但数字是错的。数值由誊写者负责，抽样人工核对，再由手算断言兜底。

**代价**：誊写是人力活，规则一改要两处同步。

## D-08 规则带状态，缺失即抛错

**定于** 2026-09-10

四个状态：通过、存疑、驳倒、缺失。推导器遇到"缺失"抛错并说明该查哪本书，而不是拿个中值蒙混。

**为什么**：清式批评稿指出，Tier A 要求由柱高反算斗口，两本书都没给反函数，六个口径互差 8% 到 21%，选哪个决定斗口差一等以上。如果不让"我们不知道"成为一个程序能表达的状态，这个洞会被一个编出来的数字盖住，然后一路传到几何里。

**代价**：正门与大观楼现在直接抛错，Tier A 的建筑暂时造不出来。这是有意的。

## D-07 平面图先于分区建设

**定于** 2026-09-10

先用带独立核验的 workflow 综合学界复原方案，产出 `plan.json` 与 `plan.svg`，再按区域并行建设。

**为什么**：区域之间要有全局一致的边界、标高、路网和游线，手写一张大表在第三个院子就会自相矛盾。

**代价**：多花一轮 workflow。而且第一版的几何层是占位皮——19 个区域全是同一个椭圆抖出来的七顶点 blob，不表达院墙、轴线、进深。批评稿点破了这一点，补真几何是 P2。

## D-06 建筑分三档，各配一套参数集

**定于** 2026-09-10

Tier A 礼制大式走清《工程做法》斗口制，Tier B 住宅小式与 Tier C 园林杂式走《营造法原》界与提栈，另有 C-r 乡野子档（稻香村）不接任何模数链。

**为什么**：大观园有两套建筑语言。省亲主轴要贵、正、礼；一离开主轴就是明清文人园林——白粉墙、山石、曲廊、漏窗。全按官式做出来是缩小版故宫，全按园林做撑不起省亲规格。

**代价**：三套参数集的 derived 字段要对齐（`qingshi.schema.json` 的 mapping 段列了 24 个概念的对照）。

## D-05 优先级栈：原文 > 清式形制 > 法式结构 > 江南审美

**定于** 2026-09-10

曹雪芹写的是文学园林，不是工部施工图。规则冲突时原文有最终否决权。

**为什么不纯用法式**：《营造法式》是北宋官式，红楼梦是 18 世纪清代。法式只守"中国木构的基本语法"这条下限，时代形制由清《工程做法》守。

**代价**：原文自己会打架。十七回说稻香村"紧接潇湘馆隔青山"，七十四回说它"紧邻暖香坞"，而暖香坞已被别处原文锁死在东。这类冲突降级到多家复原共识裁决，被牺牲的那条原文显式记账。判决书里有 28 条这样的裁决。

## D-04 研究走带独立核验的 workflow

**定于** 2026-09-09

每章一个研究 agent，配两个反驳者（一个对原文逐字，一个对实测建筑）。两人都不驳倒记通过，一人驳倒记存疑并把双方原话抄上，两人都驳倒记驳倒并留档。

**为什么**：之前实测过，单 agent 的研究报告会把编造的数字当事实写进去，而且看起来很硬（带精确的行号和百分比）。只有独立的对抗核验能抓住。

**代价**：贵。三次挖书加起来约九百万 token，占整个项目的九成以上。但这是一次性投入，之后加建筑是填表。

**衍生的怀疑习惯**：任何单 agent 出的研究报告，架构层面的观察可以当设计模式用，精确的行号与数值别当事实引，要用先核。

## D-03 底座是推导器，不是直接建模

**定于** 2026-09-09

不手工建每一栋房子，而是把营造规范编译成"模数语法 + 参数集 + 推导链 + 几何生成器"四层。

**为什么**：换一栋建筑只是换一份 spec，换一个时代或地域只是换一份参数集。已验证：同一条推导链传 `era: tang` 就算出佛光寺的举高，传 `fashi` 就是宋官式。

**代价**：前期投入大（见 D-04）。而且这套底子只覆盖中国官式与江南木构这一支；徽派马头墙、闽南燕尾脊、藏式是另外的参数集，要另挖书。大木作以外（小木装修、彩画、砖石雕饰）也不在里面。

## D-02 画风走动森式卡通

**定于** 2026-09-09

**为什么**：写实是双重为难——既为难渲染器又为难找资产。程序化几何在写实下最藏不住。卡通把观感护城河放在光照和构图上，那是程序能控制的。

**代价**：不追求照片级。真要 3A 写实得换引擎换路线。

## D-01 引擎壳取自 pallet-town-3d

**定于** 2026-09-09

那个项目验证了零资产程序化在中景可以成立：地形、天光、后期、水、散布、截图合同都能直接用。

**代价**：继承了一堆遗留——温带森林的六个树种（橡、桦、针叶）、宝可梦的材质文件（已删）、精灵球徽标（已换）、英文文案（已改）、以及一个与 three 相反的碰撞旋转约定（已改，见 PITFALLS）。

**已验证的天花板**：中景能打，近景与角色是墙。所以选了建筑加园林这个正好避开角色的题材。
